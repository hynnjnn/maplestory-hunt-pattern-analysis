# 🍁 키보드 인터럽트 로그 분석을 통한 메이플스토리 유저 사냥 패턴 데이터 분석

### 1. ❓ 문제 정의
평소와 다름없이 사냥을 하던 중, 짧은 시간 내에 거짓말 탐지기(매크로 방지 시스템)가 반복적으로 출력되는 현상을 겪게 되었다.  
개발자의 관점에서 게임의 시스템이 나의 어떤 조작 패턴을 매크로로 오인 했는지 의구심이 들었다. 시스템이 나의 입력을 기계적 반복으로 규정했다면, 실제 내 사냥 패턴이 얼마나 정형화 되어 있는지 데이터를 통해 직접 확인해보고자 프로젝트를 시작하게 되었다.

#### 🎯 분석 목표
* 나의 사냥 패턴은 매크로로 의심할 만큼 일정한가?
* 가상의 매크로 데이터와 비교 실험을 통해 오탐지 원인 규명

### 2. 📑 분석 과정

#### 🛠️ [데이터 수집: 로깅 도구 설계]
오토핫키와 같이 게임 클라이언트의 메모리에 접근하거나 직접적인 입력을 발생시키는 방식은 게임 운영 정책 위반의 소지가 있다고 판단했다. 따라서 안전하게 키보드 인터럽트를 감지할 수 있는 pynput 라이브러리를 채택하여 로깅 스크립트를 구현 후 약 30분 동안의 사냥 로그를 기록하였다.

* **수집 환경:** 실제 사냥 30분 기록
* **데이터 구조:** `[Timestamp] Key_name` 형태의 raw 데이터

#### 📊 [데이터 전처리: 범주형 데이터 매핑]
텍스트 기반의 로그는 데이터 간의 상관관계를 파악하기 어렵기 때문에 각 키의 기능적인 성격을 고려하여 정수로 변환하였다.

* **매핑 이유:**
  * 시각화를 통해 사냥 사이클의 구조를 한눈에 파악할 수 있도록 함.
  * 비슷한 성격의 키를 인접한 수치로 묶어 특정 구간에서 어떤 군집을 형성하는지 분석하기 위함

#### 🔄 [데이터 정제: 사이클 동기화]
단순히 설치기의 쿨타임인 60초(절대적인 시간)로 사이클을 구분할 경우, 조작이 밀릴 때마다 패턴이 어긋나 비교 분석이 불가능해진다. 이를 해결하기 위해 설치기의 입력 시점을 기준으로 사이클을 분할하여 이벤트를 기반으로 사이클을 동기화 하였다.  
사냥 빌드마다 트리거 키가 다를 수 있기 때문에 분석 시 트리거가 될 키를 입력받아 해당 키 입력 시점을 t=0으로 재설정하여 모든 사이클을 동일 선상에 배치하였다.

#### 🔵 Hunting Pattern Density Scatter
'Hunting Pattern Density Scatter' 그래프는 전체 사이클 데이터를 동일 시간대의 키 입력 빈도에 따라 포인트 크기와 색상을 다르게 시각화 한 것이다.

* **설치 및 회수 구간(0s ~ 12s, 58s ~ 60s):** 그래프의 시작과 끝 지점에서 설치 스킬과 이동기(Dash/Jump, Move)키의 밀도가 높은 양상을 보인다. 주력 스킬의 밀도는 비교적 낮다.
* **주력기 반복 구간(12s ~ 58s):** 제자리 사냥의 특성 상 이동기의 빈도는 급감하고, 일정한 간격으로 높은 밀도의 주력기 포인트들이 관찰된다. 특히 13.4s / 28s / 43.2s / 57.7s에서 밀도가 높은 구간의 주기가 15초 정도로 일정한 것을 볼 수 있다. 이는 몹의 젠 시간인 7-8초의 두 배로, 아란이라는 직업이 사냥을 할 때 a키와 q키를 몹 젠 시간에 맞춰 사용하며 비교적 약한 스킬인 a키를 여러번 누르는 특징을 잘 반영하고 있다.

### 4. 🔬 분석 결과

#### 🔎 [나의 사냥 패턴은 매크로로 의심할 만큼 일정한가?]
시각화를 통해 나의 사냥 패턴이 높은 규칙성과 일관성을 가진다는 것을 확인할 수 있었다. 본 파트에서는 이러한 정형성이 통계적으로 얼마나 일정한지, 그리고 매크로 알고리즘과 비교를 통해 어느정도의 유사도를 나타내는지 정량적으로 분석 하고자 한다. 매크로 프로그램은 직접적으로 사용할 수 없기 때문에 가상의 데이터를 생성하였다.

인간의 수동 조작을 통해 생성된 시계열 데이터는 완벽히 동일한 타임스탬프에 키가 입력되지 않고, 미세한 시간 차(Lag)를 두고 대응되는 경우가 많다. 시각화를 통해 봤듯이, 나의 사냥 패턴 또한 사이클끼리 비슷한 모양을 가지지만 Lag가 존재하는 것을 볼 수 있었다. 이러한 경우 유사도를 측정할 때, 동일 시점의 포인트 간 거리만을 계산하는 유클리드 거리 방식은 적합하지 않다. 따라서, Lag가 존재하더라도 파형의 구조적 흐름과 동일한 패턴 지점을 유연하게 대응시켜 유사도를 측정하는 DTW(Dynamic Time Warping) 알고리즘을 채택하여 분석을 진행하였다.

#### 🤖 [4-1. 가상 매크로 데이터 생성]
일차원적인 매크로 프로그램은 정해진 스크립트를 일정하게 반복한다. 하지만, 요즘 사용되는 매크로 프로그램은 안티 치트 시스템의 패턴 탐지를 우회하기 위해 의도적으로 불규칙성을 추가하여 작동한다. 이러한 불규칙성을 구현하기 위해 실제 사냥 데이터에서 임의의 사이클을 추출하여 해당 사이클의 입력마다 -0.3초에서 0.3초 사이의 난수를 더해 실제 데이터와 동일한 사이클만큼 연속으로 수행하는 스크립트를 작성하였다.

#### 📝 Actual data vs Virtual macro data
두 데이터의 DTW 유사도 분석 결과는 다음과 같은 정량적 차이를 보여준다. DTW 유사도 분석에는 `fastdtw`라이브러리를 사용하였다. 예시 데이터의 경우 28개의 사이클을 가지고 있기 때문에 <sub>28</sub>C<sub>2</sub> = 378가지의 모든 사이클 쌍을 계산하여 평균값을 도출했다.

* **실제 사냥 데이터:** 평균 DTW 거리(오차) 109.24 / 최종 패턴 유사도 97.72%
* **가상 매크로 데이터:** 평균 DTW 거리(오차) 55.89 / 패턴 유사도 98.84%

분석 결과, 난수 오차를 부여한 가상 매크로 데이터가 실제 본인의 사냥 데이터보다 평균 오차가 절반 수준으로 적었고, 유사도는 약 1.12%p 더 높게 측정되었다. 실제 인간이 조작한 사냥 패턴의 유사도가 97.72%를 기록했다는 것은, 거시적인 관점에서 안티치트 시스템이 해당 조작을 매크로 프로그램으로 의심하기에 충분하였음을 증명한다.

여기서 흥미로운 점은 기계적인 불규칙성만을 추가한 매크로 패턴과, 나의 수동 조작 패턴의 유사도 차이가 단 1.12%p 밖에 나지 않는다는 사실이다. 이는 극단적인 예시로, 본인보다 더 높은 숙련도를 가진 인간과 더 고도화된 매크로 알고리즘을 시스템이 통계적으로 구별하는 것은 불가능한 영역임을 시사한다.

평균 오차의 경우 가상 매크로(59.89)와 실제 데이터(109.24)는 약 두배 가까운 격차를 보였다. 이는 가상 데이터를 생성할 때 적용한 사이클 복제 방식의 특성에서 기인한 것으로 분석된다. 가상 매크로 데이터는 원본 데이터 내에서 전형적이고 정돈된 형태를 가진 사이클을 표준삼아 생성되었다. 기반이 되는 뼈대 파형 위에 미시적인 난수만 얹었기 때문에, 378개의 조합을 서로 비교해도 거시적인 이탈이 일어나지 않아 오차 거리가 55.89 수준으로 좁게 묶이게 된다.  

반면, 실제 사냥 데이터는 피로도, 룬 시스템, 엘리트 몬스터 시스템 등 사이클마다 변수가 존재하기 때문에 조합 간의 거리가 상대적으로 넓게 분포할 수 밖에 없다. 만약 가상 매크로 데이터를 생성할 때 의도적으로 돌출구간을 추가하거나, 하나의 사이클이 아닌 여러 형태의 사이클을 무작위로 섞어서 기준으로 삼았다면 이 오차의 차이 마저도 좁혀졌을 것이다.

### 5. 🏁 결론
본 프로젝트는 "나의 사냥 조작이 왜 매크로로 의심받았는가?"에 대한 의구심에서 시작되어, 키보드 인터럽트 로깅 및 DTW 유사도 분석을 통해 그 원인을 규명해보았다.  
결론적으로, 단순히 사냥 패턴의 거시적 유사도만을 기준으로 매크로와 인간을 구분하는 것은 불가능에 가까워 보인다. 인간은 숙련도가 쌓일수록 기계처럼 정교해지고, 매크로는 고도화될수록 인간 특유의 불규칙성을 의도적으로 추가할 수 있기 때문이다. 실제로 게임사가 인게임에서 주기적으로 '룬 시스템'이나 '엘리트 몬스터/보스'등 돌발 이벤트를 강제로 발생시키는 이유도 바로 여기에 있다고 볼 수 있다. 일반적인 사냥 패턴 이외에 돌발 이벤트에 대한 수동적인 대처를 요구하는 설계적 장치인 것이다.

매크로 의심 유저를 표적으로 삼는 거짓말탐지기나 비올레타 같은 안티치트 시스템 역시 작업장과 비인가 프로그램을 검거하기 위한 필수적인 도구이다. 그러나 일반 유저들의 입장에서는 사냥의 피로도와 불쾌감을 높이는 양날의 검이 된다. 사냥을 자주 하는 유저라면 거짓말탐지기나 비올레타에 실수해서 진실의 방에 갇힌 경험이 한번씩은 있을 것이라 생각한다.  

게임 보안 시스템은 단순히 '얼마나 똑같이 반복하는가'라는 일차원적 검사에서 벗어나야 한다. 23년간 축적된 게임 내의 많은 데이터를 기반으로 선량한 유저의 게임 경험을 해치지 않으면서도 악성 유저를 정확히 골라내는 건강한 안티치트 생태계를 구축할 필요가 있다.
